# 在线闭环：本地视觉模型监督 π0.5

2026-11-10。本次所有新代码、配置、启动脚本和测试均在 `/home/user/ty/new/agent`。没有改写外部 SDK/模型仓库，没有下载模型，没有驱动实机。

## 1. 运行组成

| 进程/模块 | 职责 | 接口 |
|---|---|---|
| 你后续部署的视觉千问或其他 VLM | 看近期三视角图像、状态和记忆，解释异常并选择下一技能 | 本地 `POST /v1/chat/completions`，非流式多图输入、JSON 输出 |
| agent 自有 π0.5 阶段服务 | 复用现有 JAX 权重加载与动作变换，接收动态阶段指令 | `ws://127.0.0.1:8010`，原有普通/RTC 协议增加观测中的 `agent_epoch` 与回执 |
| agent 在线进程 | 读 SDK 观测、异步调用 VLM、决策校验、单一控制线程 | SDK 只读 reader、控制 body、Pi05Controller |
| 既有硬件/相机发布进程 | 发布观测、接收设备命令 | 沿用当前 ROS 工位配置 |

在线进程替代原来的“终端三推理执行进程”，并持有唯一设备控制权。硬件/相机发布进程可以继续复用。不能同时运行旧 workbench 执行任务和新的 agent 执行任务。

## 2. 两个已发现问题如何在本目录解决

### 固定 prompt

`stage_server.build_policy()` 调用原 `pi05_server.runtime.create_policy(..., override_prompt=False)`，不修改原 profile，也不篡改全局变量。仅允许登记技能对应的规范指令；推理结果返回 `effective_prompt`、`agent_epoch`，客户端逐次核对。

这是加载同一模型的另一个服务入口，不是转发到旧固定 prompt 服务的 HTTP/WebSocket 代理。后者无法改变模型实际接收到的语言。

原 checkpoint 的维度、动作语义、相机布局、归一化和哈希校验继续执行。现有加载器不接受的导出格式仍会拒绝，不通过删除校验强行加载。服务可以接受阶段文字不代表该 checkpoint 已经学会这些技能；后续阶段模型需要相应训练与验证。

### reset 空操作

在线执行不依赖 `Pi05Policy.reset()` 切换技能：

1. 控制所有者暂停普通动作派发。
2. `body.stop()` 等待双臂双手的保持回执。
3. 关闭旧控制器、旧推理连接与线程；旧时间轴和 RTC 前缀不再使用。
4. 从保持后的新观测重新调用视觉模型，检查目标技能条件。
5. 用新 epoch 创建独立客户端、Policy、Pi05Controller；此时只准备，不输出动作。
6. 再读一次新鲜状态，检查准备期间状态变化与证据时效。
7. 提交阶段记忆，激活新控制器，由原有首帧准入、轨迹处理和关节约束控制起步。

任何保持、关闭、准备或激活失败，停止普通执行并记录错误。没有把停止等同于松手、回 Home 或断电。

## 3. 视觉服务输入输出

配置默认地址只是预留，不会启动或下载千问：

```json
{
  "vlm_url": "http://127.0.0.1:8009/v1/chat/completions",
  "vlm_model": "Qwen3-VL-2B-Instruct"
}
```

请求包含系统任务说明、最近若干次三视角图像、图像时间与帧 ID、当前实测关节、当前阶段/epoch、事件记忆及控制保持状态。图片是 JPEG data URL，最长边默认 512；保留每幅图的源时间。只连接本地地址，不调用云端服务。

响应示例（ID 必须来自当前请求，下面只是格式）：

```json
{
  "request_id": "req-42",
  "observation_id": "obs-42",
  "stage_epoch": 3,
  "observed_activity": "S6",
  "target_id": "fruit-2",
  "facts": {
    "right_stable": {"value": "TRUE", "frame_ids": ["obs-42:cam0"]},
    "left_clear": {"value": "FALSE", "frame_ids": ["obs-42:cam1"]},
    "fruit_remaining": {"value": "TRUE", "frame_ids": ["obs-42:cam0"]},
    "contact_releasable": {"value": "UNKNOWN", "frame_ids": ["obs-42:cam1"]}
  },
  "events": [],
  "intent": "OBSERVE",
  "next_skill": null,
  "reason": "目标仍在串上，左手遮挡接触位置，暂不能确认退出条件。"
}
```

事实只有 TRUE/FALSE/UNKNOWN。不能提供不存在的帧 ID，也不能由视觉模型伪造 `control_fault`。后者由本地执行状态产生。事件 ID 和目标 ID 要跨帧保持；无法关联时不结算成功数量。

技能菜单：`lift_truss`、`pick_and_deposit`、`return_truss`、`reposition_truss`、`return_bare_stem`、`disengage_left`、`deposit_held_fruit`。

视觉模型的 `next_skill` 是候选，不是命令。若与当前物理条件及任务图允许的技能冲突，执行端保持并重新观察。例如仍有果实，不能因模型说“结束”就跳到裸杆收尾。

缺失字段、非 JSON、截断输出、错误 epoch、缺失帧引用、请求超时及过期响应都会被拒绝。事实与历史规则仍可能拒绝一个格式正确的结果。

## 4. 异步与时效

- 视觉请求在单独 daemon worker 中执行，最多一个在途请求，不堆积过期图像。
- SDK 控制在单一控制线程中持续运行；同技能刷新沿用原 RTC。
- 高层结果最大时龄和设备控制观测时龄分开设置；控制器原有的新鲜度检查不放宽。
- 阶段切换要求保持后两次不同源图像上的一致候选，再检查准备后的实测状态变化。
- 持续没有有效监督、控制线程故障或源观测失效时，退出运行并尝试确认保持。
- VLM 调用频率、超时、图片数量/尺寸都是待测参数；不保证 2B 模型在默认 3 秒内完成任务判断。

首版采用“保持后再确认”的语义切换，会增加边界耗时。它已经是在线执行路径；后续可在验证退出状态和时延后优化连续交接。

## 5. 后续启动顺序

### 仅检查接口配置（当前就可运行）

```bash
cd /home/user/ty/new/agent
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 -B -m tomato_agent.online.runner \
  --config configs/online.example.json
```

不会连接模型或机器人。模板 `validated_skills` 为空；后续填写实际完成模型验证的技能，避免把候选恢复能力当作已有能力。

### 启动阶段 π0.5 服务

使用已有 pi05-server 的 Python 环境和本目录入口。先检查 checkpoint：

```bash
cd /home/user/ty/new/agent
bash scripts/serve_stages.sh --checkpoint /实际权重目录 --check-only
```

检查通过后去掉 `--check-only`，会加载并预热已有 π0.5 权重，成功监听后生成本目录 `runtime/pi05-stage-model.json`。不覆盖 mono 的 `.lia/pi05-active-model.json`。

服务默认支持菜单中的全部规范指令，可用 `--skills lift_truss pick_and_deposit ...` 限制接口登记技能。服务登记仍不代表实机验证通过。

### 接入视觉服务

你部署本地视觉模型后，在 `configs/online.example.json` 的副本中填入服务地址、模型名、技能列表和新的日志路径。接口需支持多图 messages、`response_format={"type":"json_object"}` 和非流式回复。不需要改 SDK 仓库。

### 在线执行

硬件/相机发布进程应已运行，旧采摘执行进程应已退出。使用本目录脚本激活现有已安装的 ROS 环境，不调用 pixi 安装/更新：

```bash
cd /home/user/ty/new/agent
bash scripts/run_online.sh --config configs/online.local.json --execute
```

该命令会获取设备控制权并可能运动。本次没有运行此命令。默认启动脚本不自动回 Home，也不修改设备限值。

日志路径、生成的模型合约、缓存与 ROS 日志均指向 agent 目录；输出文件已存在时拒绝覆盖。SDK 模型资源和设备锁等本体内部实现仍沿用原 SDK，后续真机运行时应按工位环境配置其运行目录。
